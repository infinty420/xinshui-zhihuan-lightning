# 薪税智算 · 闪电校验

面向**多客户薪酬个税交付**的批量算薪与校验引擎。
把客户形态各异的工资表丢进来，输出一份口径统一、可追溯、带异常清单的标准化算薪报表。

> **开源底座**：本项目二次开发自 GitHub 开源项目
> [ikiwihome/income-calc](https://github.com/ikiwihome/income-calc)（MIT License），
> 复用其累计预扣法计算引擎与城市社保公积金政策数据，并针对批量交付场景重建为 Python 内核。
> 原始代码保留在 `vendor/income-calc/`。

---

## 一、它解决什么

| 交付痛点 | 本项目的处理 |
|---|---|
| 每家客户工资表表头都不一样 | 内置 60+ 标准字段别名词典，自动识别「基本工资/底薪/base/岗位薪」等写法，识别结果可人工修正 |
| 表形态各不相同 | 自动识别长表（行=人×月）、宽表（行=人，月份横向铺开）、单月表 |
| 社保公积金基数上下限记不住 | 政策库按城市×年度×半年度配置，自动 clamp，超限时进异常清单 |
| 算完不敢交付，怕算错 | 闪电校验：内部勾稽 + 与客户既有结果逐人逐月比对，差异分「重大/小额」两级 |
| 年终奖怎么计税更划算 | 单独计税与并入综合所得两方案全量试算，自动择优并保留对比值 |
| 客户问"依据什么政策算的" | 报表内置「政策参数与说明」页，列明本次使用的税率表、基数区间、扣除标准 |

## 二、能力矩阵

- **月度批量核算**：累计预扣预缴法，逐月计算应纳税所得额、跳档、本月应预扣税额、实发工资
- **年度批量核算**：全年汇算清缴，输出汇算应纳税额与应退/应补税额
- **年终奖**：单独计税（按月换算税率表）/ 并入综合所得，自动择优（政策有效期至 2027-12-31）
- **在职区间**：支持年中入职、年中离职，累计减除费用按实际申报月数计算
- **跨期接续**：可导入截至上期的累计收入/五险一金/扣除/已预扣税额，用于中途接手的历史系统迁移
- **多格式**：`.xlsx` `.xlsm` `.xls` `.csv`（CSV 自动识别 UTF-8 / GBK）
- **多 Sheet**：自动挑选最像工资表的 Sheet
- **表头探测**：自动跳过标题行说明行，定位真实表头
- **五险一金**：客户给金额则直接用；未给则按申报基数 × 比例推算并封顶保底
- **集团批量**：一个目录下多家主体工资表一次跑完，逐主体独立出表 + 汇总统计

### 性能基线

9,000 人 × 8 城 × 12 月 = **108,000 条**记录：

| 环节 | 耗时 |
|---|---|
| 批量薪税计算 | 14.99 秒 |
| 闪电校验 | 2.25 秒 |
| **合计** | **17.24 秒** |

## 三、快速开始

### 环境

```bash
pip install pandas openpyxl pyyaml fastapi uvicorn python-multipart xlrd
```

### 命令行

```bash
# 1) 先看工资表被识别成什么样（不计算，用于确认列映射）
python cli.py inspect 客户A工资表.xlsx

# 2) 批量核算，输出标准化算薪报表
python cli.py run 客户A工资表.xlsx --city 上海 --year 2026 --client "客户A" -o 客户A_2026算薪报表.xlsx

# 3) 单月表（表内无月份列时必须指定月份）
python cli.py run 客户B_2026年3月.csv --city 深圳 --year 2026 --month 3 -o out.xlsx

# 4) 集团级批量：一个目录下多家主体工资表一次跑完（18 家主体场景）
python cli.py group ./各主体工资表 --year 2026 -o ./集团报表

# 5) 启动 Web 工作台
python cli.py serve --port 8765
```

流程：**上传 → 确认列映射 → 填参数 → 核算 → 看校验结果 → 下载报表**

### 作为库调用

```python
from core.policy import Policy
from core.pipeline import RunOptions, run_pipeline

policy = Policy.load()
outcome = run_pipeline(RunOptions(
    input_path="客户A工资表.xlsx",
    out_path="客户A_算薪报表.xlsx",
    city="上海", year=2026, bonus_method="auto", client="客户A",
))
print(outcome.summary())          # 校验摘要
print(outcome.validation.issues)  # 异常清单
```

## 五、标准化报表结构

每次核算输出一份 Excel，含 7 个固定 Sheet：

| Sheet | 内容 |
|---|---|
| 算薪明细表 | 逐人逐月 32 个字段：应发、各社保基数与缴纳额、专项附加扣除、累计预扣过程、本月个税、实发 |
| 月度汇总表 | 按月汇总人数、应发、五险一金、个税、实发 |
| 年度汇总表 | 逐人年度累计 + 汇算清缴 + 应退补税 + 年终奖两方案对比 |
| 社保公积金明细表 | 基数与各项缴纳额，便于与社保系统逐项核对 |
| 异常校验清单 | 闪电校验输出，按错误/警告/提示三级着色 |
| 差异比对表 | 引擎重算 vs 客户既有结果，逐人逐月逐项 |
| 政策参数与说明 | 本次计算所依据的税率表、基数区间、扣除标准、声明 |

## 六、闪电校验规则

| 规则码 | 级别 | 说明 |
|---|---|---|
| V001 | 错误 | 收入明细加总 ≠ 应发工资合计（客户提供 2 项以上明细时才校验） |
| V002 | 错误 | 实发工资勾稽不平：应发+奖金−五险一金−个税 ≠ 实发 |
| V003 | 错误/警告 | 与客户既有结果差异（≥100 元判错误，否则警告） |
| V004 | 警告 | 社保申报基数超出政策上下限（已自动封顶/保底） |
| V005 | 警告 | 公积金申报基数超出政策上下限 |
| V006 | 警告/提示 | 公积金缴存比例越界，或实缴比例与配置不符 |
| V007 | 错误/警告 | 专项附加扣除为负，或合计超过常规上限 |
| V008 | 警告/提示 | 月度应发或个税环比剧烈波动（调薪/奖金/跳档） |
| V009 | 错误/警告/提示 | 月份重复、缺失不连续、全年数据不完整 |
| V010 | 警告 | 姓名/证件号缺失或长度异常 |
| V011 | 错误 | 员工编号重复导入 |
| V012 | 错误 | 金额出现负值 |
| V014 | 提示 | 政策口径提示：暂行标准、年终奖择优结果 |

阈值集中在 `policies/national.yaml → validation` 中调整。

## 七、政策库扩展

### 新增城市

在 `policies/cities.yaml` 的 `cities` 下复制任一城市节点修改即可，**不需要改任何代码**：

```yaml
  chengdu:                       # 城市代码（拼音）
    name: 成都                    # 中文名，用于匹配表内的「参保城市」列
    province: 四川
    rent_deduction: 1500         # 住房租金扣除档位
    defaults:                    # 个人缴纳比例 %
      pension: 8
      medical: 2
      medical_fixed: 0           # 医疗固定额（北京为 3 元/月）
      unemployment: 0.5
      housing: 7
      supplemental_housing: 0
    housing_rate: [5, 12]        # 公积金比例可选区间
    supplemental_housing_rate: [0, 12]
    years:
      2026:
        periods:                 # 半年度区间，社保基数通常 7 月调整
          - { months: [1, 6],  pension: [4511, 22555], medical: [4511, 22555],
              unemployment: [4511, 22555], housing: [2100, 31378] }
          - { months: [7, 12], pension: [4511, 22555], medical: [4511, 22555],
              unemployment: [4511, 22555], housing: [2100, 31378], provisional: true }
```

`provisional: true` 表示官方口径尚未公布、沿用最近已公布标准，报表会明确标注。

### 新增年度

在目标城市的 `years` 下增加年度节点即可，无需改代码。

### 城市覆盖范围

当前内置 **上海、北京、广州、深圳、杭州、南京、合肥、芜湖**，覆盖 2023–2026 年度。

## 八、新客户交付 SOP

1. **收表**：拿到客户工资表（任意格式），先跑 `python cli.py inspect 工资表.xlsx`
2. **核映射**：确认自动识别的列映射；有未识别列就在 Web 界面手工指定，或直接往 `core/schema.py` 的别名词典里补别名
3. **定参数**：确认参保城市、核算年度、是否单月表、年终奖计税方式
4. **跑核算**：`run` 出报表，或直接看控制台的校验摘要
5. **看清单**：重点看「异常校验清单」中的**错误**级条目与「差异比对表」
6. **对差异**：若客户表自带个税/实发列，工具会自动比对；差异集中的月份通常指向客户侧算法口径问题（如误用按月单独计税、专项附加扣除漏项、社保基数未封顶）
7. **交付**：导出 Excel 报表，「政策参数与说明」页可直接作为交付口径依据

## 十、边界与声明

- 五险一金默认只计算**个人缴纳部分**；单位部分、企业年金、商业保险不在核算范围内
- 大病医疗仅在年度汇算时扣除（超 15000 元部分，限额 80000 元），不进月度预扣
- 一次性收入仅覆盖工资薪金与全年一次性奖金；劳务报酬、稿酬、特许权使用费未纳入
- 城市政策中标注「暂行口径」的区间沿用最近已公布标准，官方公布新口径后请更新 YAML
- 计算结果供薪酬核算参考，实际申报以主管税务机关与社保经办机构为准
