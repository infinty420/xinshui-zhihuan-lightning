# 薪税智算 · 闪电校验 —— 项目成果说明

**申报主体**：上海外服薪数据科技有限公司
**服务对象**：三菱化学集团 18 家经营主体
**文档用途**：东兰劳动竞赛推荐表配套成果说明
**编制日期**：2026 年 10 月

> 本文档所有能力描述均可通过随附系统实际运行复现，不以概念演示替代真实效果。

## 一、项目背景与要解决的问题

三菱化学集团在中国境内设有 18 家独立经营主体，需完成 2024—2025 年度全员薪税核算工作。业务侧长期面临四类结构性困难：

| 困难 | 具体表现 | 业务影响 |
|---|---|---|
| 报表模板不统一 | 18 家主体各自沿用不同表头命名、不同表形态（明细长表 / 年度宽表 / 单月表），字段叫法互不兼容 | 每次核算都需人工逐张表梳理列含义，重复劳动无法沉淀 |
| 计税口径不一致 | 各主体计税参数、社保公积金基数上下限、专项附加扣除口径存在差异 | 结果缺乏横向可比性，集团层面难以汇总复核 |
| 人工核算效率低 | 薪税计算与数据核对全靠手工，单周期投入大量工时 | 极易出现交付延期，风险集中在下游 |
| 薪酬人员无编程能力 | 规则调整、数据复盘、报表变更均需提需求给研发排期 | 业务响应受制于研发资源，自主迭代能力弱 |

本项目与研发共同推进，目标是用「标准化规则 + 自动核算 + 智能比对」替代人工逐行核对，把薪税核算从**人力密集的手工作业**转为**规则驱动的自动化流水线**。

---

## 二、总体思路

构建 `规则配置 → 数据适配 → 批量核算 → 双向校验 → 标准报表` 的闭环，把专业判断沉淀为可复用配置，把重复计算交给程序：

```
多格式工资表
      │
      ▼
① 多模板适配   表头自动探测 · 列名智能映射 · 表形态自动识别
      │
      ▼
② 薪酬计算内核  累计预扣预缴法 · 年度汇算清缴 · 年终奖择优
      │
      ▼
③ 闪电校验     内部勾稽校验（12 类规则） + 与客户结果双向比对
      │
      ▼
④ 标准化报表   7 个固定 Sheet，口径统一，可直接交付
```

**核心设计取舍**：把「口径」与「代码」彻底分离——所有政策参数、字段别名、校验阈值全部落在外部配置文件里。业务人员调整规则不需要改一行程序，这正是"薪酬自主落地能力"的技术实现方式。

## 三、三大核心模块（已实现）

### 模块一：多模板 Excel 标准化转换

解决"18 家主体报表模板不统一"的问题。

| 能力 | 说明 |
|---|---|
| 多格式接入 | 支持 `.xlsx` `.xlsm` `.xls` `.csv`，CSV 自动识别 UTF-8 / GBK 编码 |
| 多表定位 | 一个工作簿含多个 Sheet 时，自动挑选最像工资表的那张 |
| 表头探测 | 自动跳过企业抬头、说明行、单位行，定位真实表头行 |
| 表形态识别 | 自动区分**长表**（一行=员工×月）、**宽表**（一行=员工，月份横向铺开）、**单月表**；宽表自动展开为逐月记录，并跳过未入职/已离职的空月 |
| 列名智能映射 | 内置 48 个标准字段、420 条别名。`工号/员工编号/职工号/empno`、`应发合计/应发工资/税前工资`、`社保基数/社保缴费基数/社保参保地` 等写法均可自动归一 |
| 人工兜底 | 识别结果全量可视，未命中项可在界面手工指定，或补充别名后永久生效 |

**实测结论**：构造 3 家主体、3 套完全不同表头方言的工资表（上海长表用`工号/应发合计/社保缴费基数`、北京宽表用`员工编号/1月应发工资`、广州单月表用`职工号/应发工资/参保地`），系统零改代码全部正确解析，城市各自正确识别，字段映射无遗漏。

### 模块二：本地算薪平台

解决"计税口径不统一、人工核算耗时"的问题。

| 能力 | 说明 |
|---|---|
| 累计预扣预缴法 | 按月度累计计算应纳税所得额、自动跳档、逐月应预扣税额，与税法口径完全一致 |
| 年度汇算清缴 | 全年清算，输出汇算应纳税额与应退/应补税额 |
| 年终奖择优 | 全年一次性奖金「单独计税」与「并入综合所得」两方案全量试算，自动取税负更优者，并保留对比数据供复核 |
| 城市政策库 | 内置 8 城（上海、北京、广州、深圳、杭州、南京、合肥、芜湖）× 4 个年度（2023—2026），含社保公积金基数上下限、缴纳比例、住房租金扣除档位 |
| 半年度基数调整 | 正确处理社保基数每年 7 月随社平工资调整的区间切换 |
| 基数自动封顶保底 | 申报基数超限自动 clamp，并进入异常清单提示 |
| 在职区间 | 支持年中入职、年中离职，累计减除费用按实际申报月数计算 |
| 跨期接续 | 可导入截至上期的累计收入、五险一金、扣除、已预扣税额，用于中途接手的历史系统迁移 |
| 集团批量 | 一条命令跑完一个目录下多家主体的全部工资表，逐主体独立出表，汇总统一呈现 |

**实测结论**：以月薪 20500 元、上海 2026 年政策的员工为例，1 月应预扣个税 252.38 元、年度累计应纳税所得额 100950 元、全年月度预扣合计 7575 元——与逐月手工推算完全吻合。年终奖 60000 元场景下，单独计税全年税负 13365 元，并入综合所得 15270 元，系统自动择优为单独计税，为员工节省税负 1905 元。

### 模块三：税金双向校验（闪电校验）

解决"人工逐行核对出错率高、流程繁琐"的问题。这是本项目区别于普通计算器的关键能力。

**第一向：内部勾稽校验**（校验工资表自身是否自洽、是否合规）

| 规则码 | 校验内容 |
|---|---|
| V001 | 收入明细加总 ≠ 应发工资合计 |
| V002 | 实发工资勾稽不平（应发+奖金−五险一金−个税 ≠ 实发） |
| V004 / V005 | 社保 / 公积金申报基数超出政策上下限 |
| V006 | 公积金缴存比例越界，或实缴比例与配置不符 |
| V007 | 专项附加扣除为负，或合计超过常规上限 |
| V008 | 月度应发或个税环比剧烈波动 |
| V009 | 月份重复、缺失不连续、全年数据不完整 |
| V010 | 姓名 / 证件号缺失或长度异常 |
| V011 | 员工编号重复导入 |
| V012 | 金额出现负值 |

**第二向：与客户既有结果比对**

逐人、逐月、逐项比对个税、实发工资、五险一金三大项，差异按金额分级：**≥100 元判为错误，小额尾差判为警告**，避免无效告警淹没真问题。

**实测结论**：在样例数据中刻意植入客户侧最常见的错误算法——**误用「按月单独计税」而非累计预扣法**，系统准确抓出 60 处不一致，并定位到具体员工、具体月份、具体金额（如张伟 1 月个税：引擎重算 252.38 元 vs 客户提供 631.25 元，差异 −378.87 元）。这类差异若靠人工核对，一张 54 行的表就需要反复推演才能定位。

## 四、风险管控与合规保障

| 措施 | 实现方式 |
|---|---|
| 数据物理隔离 | 全部计算在本机完成，工资数据不上传任何外部服务器，无外部 API 依赖 |
| 内网闭环 | 政策参数、计算规则、校验逻辑均本地运行，断网可用 |
| 口径可追溯 | 每份报表内置「政策参数与说明」页，列明本次使用的税率表、基数区间、扣除标准、政策有效期与声明 |
| 暂行口径标注 | 官方尚未公布的年度/半年度口径明确标记为「暂行」，沿用最近已公布标准，避免误用冒充权威 |
| 敏感数据最小化 | 报表仅输出核算必需字段；证件号按需脱敏，不参与计算逻辑 |
| 结果可复核 | 所有中间量（累计应纳税所得额、适用税率、累计已预扣税额）全部落表，审计链路完整 |

## 五、应用场景

本项目已实现为通用能力，**可复用至各类客户的薪酬个税交付**：

- 适配多格式工资表，输出标准化格式的算薪报表
- 月度批量薪资个税核算
- 年度批量薪资个税核算与汇算清缴
- 集团多主体并行核算与结果汇总
- 客户既有算薪结果的质量校验与差异追溯
- 政策调整后的历史数据批量重算

**新增主体或新增年度无需修改程序**：在政策配置文件中复制一个节点、修改参数即可生效。

## 六、预期成效

### 效率提升

以 18 家主体、全员全年度核算为基准：

| 环节 | 人工模式 | 自动化模式 |
|---|---|---|
| 模板梳理与字段对齐 | 每家主体单独梳理，重复劳动 | 自动识别，一次配置长期复用 |
| 薪税计算 | 逐人逐月手工计算，数天工作量 | 程序批量计算，十余分钟完成 |
| 数据核对 | 逐行比对，易漏易错 | 双向校验自动比对并定位差异 |

**实测性能基线**：以 9,000 名员工、覆盖 8 个参保城市、全年 12 个月的 **108,000 条**记录为压测样本：

| 环节 | 耗时 |
|---|---|
| 批量薪税计算（含累计预扣、年度汇算、五险一金封顶保底） | 14.99 秒 |
| 闪电校验（12 类勾稽规则 + 差异比对） | 2.25 秒 |
| **合计** | **17.24 秒** |

同等数据量下人工逐人逐月核算需数天工作量。核算周期由"数天"压缩至"十余分钟"量级，模板开发与规则调整不再需要研发排期。数据规模扩大时耗时近似线性增长，无性能瓶颈。

### 成本降低

- 无需人工编码开发，减少研发资源重复消耗
- 脚本与配置一次沉淀、多年复用，避免反复开发的资源浪费
- 业务人员经简单培训即可自主维护规则，降低对研发资源的依赖

### 质量提升

- 全流程自动校验替代人工核对，从机制上消除计算偏差
- 差异精准标记到人、到月、到项，复核工作量大幅下降
- 合规化运算保障薪税服务精准规范，降低交付延期与差错风险

### 能力沉淀

降低薪酬业务数字化门槛，提升薪酬业务自主运维能力。工具可重复使用、适配多行业客户薪酬交付与个税核对业务，实现**服务效益与营收效益双向增长**。
